# Database Model

## 1. Overview

The current database model is still in an early stage.

The database only contains authentication-related application tables generated for the Phoenix authentication system. Business tables such as collections, products, carts, orders, inventory, recipients, and store settings have not been implemented yet.

This document describes current database reality only. Future database proposals live in separate research files.

## 5. `users` Table

Table name:

```text
users
```

Related modules:

```text
Schema:  CaHeoShop.Accounts.User
Context: CaHeoShop.Accounts
Scope:   CaHeoShop.Accounts.Scope
```

Fields:

| Field | Type | Required | Notes |
| --- | --- | --- | --- |
| `id` | primary key | yes | Generated by Ecto/database. |
| `email` | `citext` in database, `:string` in schema | yes | Case-insensitive email identity. |
| `hashed_password` | `string` | no | Stores hashed password when password auth is used. Redacted in schema. |
| `confirmed_at` | `utc_datetime` | no | Set when an account is confirmed. |
| `inserted_at` | `utc_datetime` | yes | Generated by Ecto timestamps. |
| `updated_at` | `utc_datetime` | yes | Generated by Ecto timestamps. |

Virtual schema fields:

| Field | Type | Purpose |
| --- | --- | --- |
| `password` | `:string`, virtual, redacted | Registration/password changes before hashing. |
| `authenticated_at` | `:utc_datetime`, virtual | Tracks recent authentication/sudo-mode state from session tokens. |

Indexes and constraints:

```elixir
create unique_index(:users, [:email])
```

Authentication behavior:

- `email` is required, max length 160, and validated with a simple email format check.
- `email` uses a unique constraint.
- `password` is required only when setting/changing a password.
- passwords are hashed with `Bcrypt.hash_pwd_salt/1`.
- `confirmed_at` is set by `CaHeoShop.Accounts.User.confirm_changeset/1`.

Purpose:

`users` stores the account identity used by login, settings, email changes, password changes, session lookup, and authenticated LiveView scopes.

## 6. `users_tokens` Table

Table name:

```text
users_tokens
```

The actual table name is `users_tokens`, not `user_tokens`.

Related modules:

```text
Schema:  CaHeoShop.Accounts.UserToken
Context: CaHeoShop.Accounts
Related user schema: CaHeoShop.Accounts.User
```

Fields:

| Field | Type | Required | Notes |
| --- | --- | --- | --- |
| `id` | primary key | yes | Generated by Ecto/database. |
| `user_id` | foreign key to `users.id` | yes | Deletes with the user. |
| `token` | `binary` | yes | Raw session token or hashed email token, depending on context. |
| `context` | `string` | yes | Token purpose, such as `session`, `login`, or `change:<email>`. |
| `sent_to` | `string` | no | Email address the token was sent to for email-based flows. |
| `authenticated_at` | `utc_datetime` | no | Authentication timestamp used for session/sudo-mode behavior. |
| `inserted_at` | `utc_datetime` | yes | Generated by Ecto timestamps. |

There is no `updated_at` column on `users_tokens`.

Relationships:

```elixir
belongs_to :user, CaHeoShop.Accounts.User
```

Foreign key behavior:

```elixir
add :user_id, references(:users, on_delete: :delete_all), null: false
```

Indexes and constraints:

```elixir
create index(:users_tokens, [:user_id])
create unique_index(:users_tokens, [:context, :token])
```

Purpose:

`users_tokens` supports authentication token workflows:

- session tokens with context `session`
- magic-link login tokens with context `login`
- email-change tokens with contexts like `change:<current_email>`

Token behavior from current code:

- session tokens are random binary tokens stored directly and valid for 14 days.
- magic-link and email-change tokens are sent as encoded tokens and stored as SHA-256 hashes.
- magic-link tokens are valid for 15 minutes.
- email-change tokens are valid for 7 days.
- session tokens may be reissued after 7 days by `CaHeoShopWeb.UserAuth`.
- logout deletes the current session token.
- password changes delete existing user tokens.

## 7. Current Authentication Model

The authentication system is centered on:

```text
CaHeoShop.Accounts
CaHeoShop.Accounts.User
CaHeoShop.Accounts.UserToken
CaHeoShop.Accounts.Scope
CaHeoShopWeb.UserAuth
```

Current route/session behavior:

- `:browser` pipeline fetches `current_scope` through `fetch_current_scope_for_user`.
- public LiveViews are mounted in `live_session :current_user` with `:mount_current_scope`.
- authenticated LiveViews are mounted in `live_session :require_authenticated_user` with `:require_authenticated`.
- templates should access the logged-in user through `@current_scope.user`.

Current login capabilities:

- email/password login
- magic-link login
- remember-me cookie backed by stored session token
- authenticated user settings
- email change confirmation
- password update
- logout with session token deletion
